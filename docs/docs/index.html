General

Codenvi lets one person drive Claude Code on several Windows PCs from an Android phone. Each PC has registered project folders. The phone sends a prompt to a project, the PC runs Claude Code on it, commits the result to a development branch and sends the answer back.

Why Codenvi

  • You own the server. One owner per installation. Prompts, replies, project names and commit messages are end-to-end encrypted, so the server only relays ciphertext.
  • No accounts. You choose one password. Each app links once with the host name and that password and then holds its own revocable credential.
  • No open ports on your PCs. Both apps connect outbound.
  • Safe by default. Work lands on codenvi-dev. Codenvi never pushes, never merges to main and never rewrites history.
  • Free and open source. MIT License, for personal use.
Start with How it works, then follow Installation to set up the server, a PC and your phone.
Codenvi is an independent open-source project. It is not affiliated with, endorsed by, or sponsored by Anthropic, PBC. "Claude" and "Claude Code" are trademarks of Anthropic, PBC. Codenvi runs the official Claude Code CLI that you install and sign in to yourself on each PC, and never sees or stores your Claude credentials. It lets an AI agent change files and run commands on your PCs, so use it at your own risk and review its changes before merging them.

How it works

Three parts work together: the Android app, a relay server you host, and the Windows app that runs Claude Code.


Android app ──HTTPS/WSS──▶ your VPS (nginx → Node.js server → PostgreSQL) ◀──HTTPS/WSS── Windows app ──▶ claude -p
   encrypts prompt                  relays ciphertext only                      decrypts, runs Claude Code,
   decrypts reply                                                               commits, encrypts reply
  1. On the phone you pick a project and send a prompt. The app encrypts it with the key of that PC.
  2. The server relays the ciphertext. If the PC is offline the job waits and runs when the PC reconnects.
  3. The Windows app decrypts the prompt and runs Claude Code in the project folder (claude -p, prompt sent on stdin). Progress streams back live.
  4. The result is committed to the development branch (codenvi-dev by default). The reply is encrypted and sent to the phone.
  5. The phone decrypts and shows the reply. You can have it read aloud, or roll back to any earlier commit from the Commits list.

On the phone

Besides the chat per project, Multimode lists every project of every connected PC on one screen and sends your message to the selected one. Voice input uses the system speech recognizer and never auto-sends: you review the text first. Read aloud uses the system text-to-speech engine.

What the dev branch means

Codenvi creates and checks out codenvi-dev when you register a project. Rolling back runs git revert on the later commits, so history is never rewritten. Merging the branch is left to you.

Installation

Setup has three parts: the server on a VPS, the Windows app on each PC, and the Android app on your phone.

1. Server

Fork the repository, then add these GitHub secrets (Settings, Secrets and variables, Actions): VPS_HOST, VPS_USER, VPS_SSH_PRIVATE_KEY and ENV_VARS. ENV_VARS holds three lines that name your server:


CODENVI_APP_NAME=codenvi
CODENVI_HOST=codenvi.example.com
CODENVI_PORT=3005

Point a DNS A record for the host name at the VPS, then push to main with [server] in the commit message:


git commit -am "Update server [server]"
git push origin main

You can also run Actions, publish, Run workflow and tick server. The JWT secret, the database password and the server password are generated on the first deploy. Read the password once on the VPS:


codenvi-admin password          # <name>-admin password

A key for the deploy can be created like this, then paste the private key into VPS_SSH_PRIVATE_KEY:


ssh-keygen -t ed25519 -C "codenvi-deploy" -f ~/.ssh/codenvi_deploy
cat ~/.ssh/codenvi_deploy.pub | ssh <user>@<vps> 'mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys'

2. Windows PC

  1. Install Git for Windows and Claude Code, and sign in to Claude Code yourself in a terminal.
  2. Download Codenvi.exe and run it. SmartScreen warns because the exe is unsigned: choose More info, Run anyway, or build it yourself.
  3. Read the disclaimer, enter the host name (CODENVI_HOST) and the password in Connect to server, and pick a name for the PC.
  4. Press Generate key and register this PC.
  5. Press Register project and pick a folder. Codenvi creates the codenvi-dev branch.

3. Android phone

  1. Download Codenvi.apk and install it (allow installing from unknown sources). Install new versions over the old one and never uninstall, so the phone stays paired.
  2. On the PC press Connect a phone. On the phone tap Scan QR code from the PC, or paste the string.
  3. Send your first prompt.

More PCs

Install Codenvi.exe on each PC and enter the same host name and password. Every PC links on its own and can be revoked on its own. The phone needs each PC's encryption key once: use that PC's Show encryption key and paste the key-only string into the phone.

Security

The server is a blind relay for content. It knows metadata such as installs, devices, project IDs, timestamps and job states, but it cannot read prompts, replies, project names, session names, commit messages or folder paths.

LayerHow
TransportTLS on every hop (HTTPS and WSS).
Message encryptionAES-256-GCM per message, with a 256-bit device key derived per PC (HKDF).
BindingThe AAD ties each ciphertext to its device, object, direction and time, so the server cannot move a prompt to another project, swap a prompt and a reply, or replay it under another ID.
Replay protectionThe desktop refuses job and prompt IDs it has already seen, and prompts older than 24 hours.
Tokens at restDPAPI-protected on the PC, Keystore-wrapped on the phone.
SessionsAccess tokens last 15 minutes; refresh tokens last 90 days and rotate. Reusing a rotated refresh token revokes that install.
Linking limitsWrong passwords count as failed attempts: 5 per minute per address. After 20 failures in an hour, new linking is switched off until codenvi-admin pairing on.

A compromised server cannot run commands on your PCs, because it cannot produce a valid encrypted prompt. The password only decides who may link to your server. It is not an encryption key.

Lost phone? Revoke it from the PC (Settings, Revoke) or run codenvi-admin revoke <id> on the VPS, then press Regenerate key on each PC.

The full specification and test vectors are in docs/crypto.md.

Admin commands

The deploy installs /usr/local/bin/<name>-admin on the VPS, where <name> is your CODENVI_APP_NAME. The examples use the default name codenvi.


codenvi-admin password                  # show the server password
codenvi-admin pair --name "Laptop"        # single-use connection string (only needed without an access key)
codenvi-admin pair --kind android         # phone string without a key (add keys on the phone later)
codenvi-admin installs                    # paired apps, versions, last seen
codenvi-admin revoke <install-id>         # cut one app off
codenvi-admin revoke --all                # emergency: cut everything off
codenvi-admin pairing off|on              # block / allow new pairings
codenvi-admin purge                       # run the nightly cleanup now
pm2 logs codenvi                          # server logs

To sign every app out of its current access token, put a new JWT_SECRET line (at least 32 random characters) in ENV_VARS and deploy again. The apps refresh automatically.

What the deploy never does

It never changes the firewall, runs apt upgrade, upgrades Node.js, edits PostgreSQL or nginx configuration, or touches other nginx sites, PM2 processes, databases or roles. nginx is only reloaded after nginx -t passes.

Release tags

In the owner's repository, pushing to main builds and deploys parts of the project depending on tags in any commit message of the push.

TagResult
[server]Tests the server, then deploys database migrations and code to your VPS.
[windows]Tests and builds the app, then commits windows/Codenvi.exe.
[android]Tests and builds the app, then commits android/Codenvi.apk.
  • With several tags the server always goes first. The apps are built only after the server deploy succeeded.
  • A push without tags starts nothing. You can also run everything by hand from Actions, publish, Run workflow.
  • Forks build and test but never sign, deploy or push binaries.
  • Every APK is signed with the same key, so it installs over the previous one and the phone stays paired.
  • Rollback is git revert of the commits after the good one, then a push with the tag again.

Build from source

Everything can be built locally. The Windows exe is a single self-contained file and the Android release is signed with your own key.

Server


cd server
npm ci
npm run typecheck
npm run build
npm test

The database tests need PostgreSQL through CODENVI_TEST_PG and are skipped without it. To run locally, copy .env.example to .env, set DATABASE_URL and JWT_SECRET, then run npm run db:migrate and npm run dev.

Windows app


cd windows
dotnet test Codenvi.Desktop.sln
dotnet publish src/Codenvi.Desktop/Codenvi.Desktop.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -o out

out/Codenvi.exe is the app itself, with no installer. Its data lives in %LOCALAPPDATA%\Codenvi.

Android app


cd android
./gradlew testDebugUnitTest assembleDebug
./gradlew assembleRelease
Back up your release keystore and its password outside GitHub. If it is lost, no future APK can update the installed app and you would have to pair the phone again. Never commit it.

See docs/building.md for signing and migrations.

System requirements

What each part needs to run, and what you need to build it from source.

To run

PartNeeds
Windows PCWindows 10 or 11, Git for Windows, and Claude Code installed and signed in. Codenvi.exe is a self-contained single file of roughly 70-110 MB.
Android phoneAndroid 8 (API 26) or newer. Voice input needs Google speech services or an offline language pack.

For the server

  • A Linux VPS (Ubuntu or Debian; Ubuntu 24.04 is what the guide uses) with SSH access as root or a user with password-less sudo.
  • A DNS A record for the server's host name, with ports 80 and 443 open.
  • Node.js 20 or newer on the VPS. The deploy stops rather than upgrading an older Node.js.
  • Your own GitHub repository (a fork) with Actions enabled.

To build from source

  • Server: Node.js 20.12 or newer and npm. PostgreSQL for the integration tests.
  • Windows app: .NET SDK 10 on Windows 10 or 11.
  • Android app: JDK 17 and the Android SDK (compileSdk 34). The Gradle wrapper downloads Gradle.
